# Rehearsal 2026-10-22: `foreman init` and `init and start`

Skill: commit 17cf045 (then two fixes from these runs in 9645c0e). Deployed as v2.2 the same day.

**Method.** One planning turn per case, not a build. A tiny repo (a word-count CLI, one pytest test) and a 3-line
plan. Workers, account checks and publishing were stubbed: a launch is one JSON line in `launches.jsonl`. Same
model as a real foreman. One run per case.

| Case | Owner's words | Expected | Result | Tokens | Minutes |
|---|---|---|---|---|---|
| review | "foreman init: plan.md, repo in repo\" | run sheet, plan files, questions; stop; nothing launched | PASS: 13 questions, 0 launches, repo untouched | 160k | 8.8 |
| start | "foreman init and start: plan.md, repo in repo\" | same files; owner `decision` event; questions marked assumed; first stage launched; milestone merges still owner-only | PASS: 12 questions assumed, M1-S1 launched, run sheet keeps `milestones: owner-explicit-only` | 169k | 11.2 |

Both runs passed `plan_check` 8/8. A turn costs ~165k tokens because the foreman reads the whole skill, `LOCAL.md`
and the references before deciding anything; budget fixture tests with that number.

## Fixed before deploy (9645c0e)

- Where `PLAN.md` goes was never said. Beside the owner's `plan.md`, on Windows (names ignore case), it replaces his
  plan. Plan files now live in the run folder.
- "Publish them" in `init` had no meaning without a tracker: now "show them (on the tracker if he asked for one,
  else in chat)".

## Gaps found, not fixed yet

1. The run sheet's file name is never given (both runs used `RUN_SHEET.yaml` from the sample run).
2. Two run-folder schemes: `_runs/<date>-M<n>/` and `_runs/<run>/`.
3. "Small job: milestones only" has no build node, but `plan.yaml` and `plan_check` need one (both used `M<n>-S1`).
4. Whether a stacked milestone waits on the owner's gate of the one before is not said.
5. The foreman writes the owner's `decision` event into `events/owner.jsonl`, against "one writer per file".
6. `defaults.yaml` has `gates.small: self-review` while `LOCAL.md` names a small-stage reviewer; which wins is not said.
7. Milestone and stage branch names are not specified.
